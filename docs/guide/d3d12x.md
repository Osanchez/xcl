# D3D12.X (`hle/d3d12x/*`)

How a console title's `d3d12_xs.dll` calls are served on a PC D3D12 device. Source: `crates/xcl/src/hle/d3d12x/`.
Related pages: the recompiler that turns console shaders into DXIL is in `gpu-recompiler.md`; the other HLE modules are in `hle.md`.
Status notes and measurements live in `HANDOFF.md` (sections named below).

## Overview

### Two backends

`backend()` decides once between `Backend::Real` and `Backend::Null` (`crates/xcl/src/hle/d3d12x/mod.rs:64`, `crates/xcl/src/hle/d3d12x/mod.rs:70`).
It picks Null when `graphics = "null"` is in the config, or when `real::init()` cannot create a D3D12 device
(`crates/xcl/src/hle/d3d12x/mod.rs:74`-`crates/xcl/src/hle/d3d12x/mod.rs:86`). The exported entry points (`D3D12XboxCreateDevice`, root-signature
serializers, ...) start at `crates/xcl/src/hle/d3d12x/mod.rs:40` and `crates/xcl/src/hle/d3d12x/mod.rs:115`.

### Mapping of console objects onto PC D3D12

The real backend hands the title genuine driver objects, each "adopted": its vtable pointer is replaced by an extended copy
(`adopt`, `crates/xcl/src/hle/d3d12x/real.rs:702`; layout described at `crates/xcl/src/hle/d3d12x/real.rs:3`-`crates/xcl/src/hle/d3d12x/real.rs:12`):

- original PC methods stay (a few overridden),
- slots past the public interface become guard thunks (`guard.rs`): a call from the game image is logged as a console-only method,
  a call from the runtime/DXGI is forwarded to the original internal method,
- console-only slots past the end are logging stubs.

Console-specific slots are installed per object kind by `class_for` (`crates/xcl/src/hle/d3d12x/real.rs:714`),
`console_remap` (`crates/xcl/src/hle/d3d12x/real.rs:841`) and `console_slots` (`crates/xcl/src/hle/d3d12x/real.rs:895`).
The device's own console methods are in `device_x.rs`, the command list's in `list_x.rs`, the queue's `PresentX` (queue #30) in
`present.rs`, the frame clock (device #78-#81) in `frame.rs`.

### Data flow

```text
 title code (game image)
   | CreateGraphicsPipelineStateX / CreateComputePipelineStateX / CreatePipelineState
   v
 device_x.rs ---> real.rs  translated_graphics_pso / translated_compute_pso / translated_mesh_stream
   |                 |  attempt(): dxc::cached_only (no compile)  --hit-->  PC PSO built in the call
   |                 |                                            --miss--> stand-in PSO now,
   |                 v                                                      pso_async worker builds the real one
   |           gpu/recomp (console shader -> HLSL -> DXC -> DXIL)  [see gpu-recompiler.md]
   |
   | CreatePlacedResourceX / CreateDescriptorHeap / command lists
   v
 device_x.rs: placed texture --> vram.rs (GPU-owned: pages/arenas) or title_textures.rs (detiled copy)
              placed buffer  --> sparse.rs (sparse windows of unified memory) / real.rs UMA buffers
 console_heap.rs: descriptor heaps in unified memory + shared PC heap
 list_x.rs / title_list.rs / console_list.rs + bind.rs: recording, console slots, root args
   |
   v  ExecuteCommandLists (real.rs q_execute_command_lists)
 title_textures::refresh -> console/title list -> PC list -> execute_with_waits
   -> readback_sparse_writes / cpu_writes_after -> title_textures::submitted -> present::note_execute
   |
   v  PresentX (queue #30) -> present.rs window + swap chain
 frame.rs clock thread <--- SetFrameIntervalX / ScheduleFrameEventX / WaitFrameEventX ; mark_flipped(token)
```

`q_execute_command_lists` is at `crates/xcl/src/hle/d3d12x/real.rs:4756`; the order above is the one it implements
(`crates/xcl/src/hle/d3d12x/real.rs:4765`-`crates/xcl/src/hle/d3d12x/real.rs:4780`).

### Console command-list format

D3D12.X code compiled into a title writes command records straight into the list object (+0x18 write pointer, +0x28/+0x30 bounds,
root-parameter headers at +0x344) and otherwise calls the list method (`crates/xcl/src/hle/d3d12x/console_list.rs:3`-`crates/xcl/src/hle/d3d12x/console_list.rs:10`,
`crates/xcl/src/hle/d3d12x/title_list.rs:3`-`crates/xcl/src/hle/d3d12x/title_list.rs:10`). XCL has two answers:

- `title_list`: a console-shaped object whose buffer never has room, so every inline write becomes a method call on the PC list behind it.
- `console_list` (compute only, opt-in with `XCL_CONSOLE_LISTS`): XCL's own list that keeps the records and converts them to PC commands at `close`.

`device_x::create_list` chooses: `console_list::enabled()` selects the record-keeping list, otherwise the PC list is wrapped by
`title_list::wrap` (`crates/xcl/src/hle/d3d12x/device_x.rs:95`, `crates/xcl/src/hle/d3d12x/device_x.rs:113`-`crates/xcl/src/hle/d3d12x/device_x.rs:115`).
Format details: `HANDOFF.md`, "D3D12.X command list format (compute) - determined on XboxBvhBuilder.dll" (line 408) and
"The console command list's own methods" (line 600).

### PSO creation path and non-blocking PSOs

1. The title calls a `Create*PipelineState`; `real.rs` first tries the translated path with `attempt` (`dxc::cached_only`, no DXC run),
   for graphics (`crates/xcl/src/hle/d3d12x/real.rs:3736`), compute (`crates/xcl/src/hle/d3d12x/real.rs:3781`) and mesh streams (`crates/xcl/src/hle/d3d12x/real.rs:4351`) when `pso_async::enabled()`.
   `attempt` is at `crates/xcl/src/hle/d3d12x/real.rs:3176`.
2. The translated paths detect a console shader with `is_console` and convert it with `console_to_dxil_for` from `gpu::recomp::pso`
   (`crates/xcl/src/hle/d3d12x/real.rs:3391`-`crates/xcl/src/hle/d3d12x/real.rs:3399`).
3. If DXIL is already cached, the PSO is built in the call. Otherwise the title gets a stand-in (`standin_graphics`
   `crates/xcl/src/hle/d3d12x/real.rs:3648`, `standin_compute` `crates/xcl/src/hle/d3d12x/real.rs:3663`, `standin_stream` `crates/xcl/src/hle/d3d12x/real.rs:3670`) and the build is submitted to a worker
   (`submit` / `submit_lazy`, `crates/xcl/src/hle/d3d12x/real.rs:3697`; see `pso_async.rs` below).
4. When the PC driver rejects a console shader, dummy shaders are used (`dummy`, `crates/xcl/src/hle/d3d12x/real.rs:3126`; `note_fallback`, `crates/xcl/src/hle/d3d12x/real.rs:3144`).

Design record: `HANDOFF.md` "Non-blocking pipeline creation" (line 1039).

### Memory (UMA)

Console GPU addresses in unified memory are the title's own addresses; memory operations go to the window buffer (`real::uma_window_buffer` (defined at `crates/xcl/src/hle/d3d12x/real.rs:202`),
referred to at `crates/xcl/src/hle/d3d12x/list_x.rs:16`-`crates/xcl/src/hle/d3d12x/list_x.rs:17`). `open_uma` (`crates/xcl/src/hle/d3d12x/real.rs:293`) opens the windows and
`check_uma_import` (`crates/xcl/src/hle/d3d12x/real.rs:228`) verifies the GPU sees CPU writes. Windows of at most 4095 MiB each are documented in
`HANDOFF.md` "Title memory above 4 GB: UMA windows" (line 1065); the UMA implementation is in `gpu/uma.rs` (see `gpu-recompiler.md`).
Placed resources are routed in `create_placed_resource_x` (`crates/xcl/src/hle/d3d12x/device_x.rs:858`) to `vram`, `title_textures` or `sparse`.

### Presentation and frame pacing

Titles do not use swap chains: they call `PresentX` (queue slot 30) with a frame token and the back-buffer resource
(`crates/xcl/src/hle/d3d12x/present.rs:5`-`crates/xcl/src/hle/d3d12x/present.rs:7`, dispatched at `crates/xcl/src/hle/d3d12x/real.rs:4688`). XCL copies it into its own window's swap chain and
tells the frame clock the token flipped. Pacing (frame interval, frame events, statistics) is `frame.rs`. See `HANDOFF.md`
"PresentX, frame pacing, the console command list layout" (line 549).

### Null device

Stand-in objects that accept and log every call, return plausible outputs and render nothing (`crates/xcl/src/hle/d3d12x/null.rs:1`-`crates/xcl/src/hle/d3d12x/null.rs:10`).
