## What it is for in our work

- **RPF9**: header fields, record tables and the plain-zlib payload (`docs/rpf9-container.md`). Cross-check for `crates/xcl/src/rpf.rs`, which scans records the same payload-first way (`crates/xcl/src/rpf.rs:1`).
- **Textures**: RDS5 and ETPF structure and chunk addressing (`docs/ttpf-rds5-etpf.md`), and the BCPack entropy layer (`docs/bcpack-entropy.md`): it states BCPack is the Xbox Series MDU rANS codec in front of BC1-BC7, the chunk codec id is the BC format number times four, and it publishes no tables or decoder. For XCL this is background for why DirectStorage BCPack requests are refused (`crates/xcl/src/hle/dstorage.rs:135`).
- **Counts**: `data/counts.md` marks every aggregate as measured or derived. Useful when sizing test samples (`XCL_SAMPLE_*` variables) against a real install.

## Usage

```sh
python3 reverse-toolkit/tools/0x52504639/scripts/validate_snapshot.py --help   # see its flags in the parser
```

`validate_snapshot.py` checks the repo's JSON and that the documents exist, then writes `data/last-check.json` (`reverse-toolkit/tools/0x52504639/README.md:80`). It does not read game files. It writes into the clone, so run it on a copy if you run it at all; the toolkit never needs it.

## Caveats

- The status list shows what is unfinished: table cipher identity, BCPack surface decoding, animation clips, map assembly (`reverse-toolkit/tools/0x52504639/README.md:12`).
- Some pages discuss cipher research on the archive tables, and `thirdparty_findings/` holds an outside measurement note about the game executable. We only note that this research exists. The toolkit does not use keys, does not decrypt anything and does not touch the executable; do not follow those pages as a procedure.
- Numbers come from the author's own copy and are not reproducible without the package.
- The weekly workflow (`.github/workflows/refresh.yml`) only dates the snapshot; it cannot update the counts (`reverse-toolkit/tools/0x52504639/README.md:80`).
